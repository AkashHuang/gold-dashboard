## 1. 贵金属价格获取方法

### 数据源（2026-07-29 起弃用 NeoData）
NeoData 不覆盖白银现货、且需付费接口。改为以下**免费公开、无需 token** 的源：

| 品种 | 来源 | 方式 | 代码 / 标识 |
|------|------|------|------|
| COMEX 黄金期货 | 腾讯 `qt.gtimg.cn` | HTTP GET（GBK 解码） | `fuGC` |
| COMEX 白银期货 | 腾讯 `qt.gtimg.cn` | HTTP GET | `fuSI` |
| 伦敦金现货 | 腾讯 `qt.gtimg.cn` | HTTP GET | `hf_XAU` |
| 伦敦银现货 | 腾讯 `qt.gtimg.cn` | HTTP GET | `hf_XAG` |
| 美元兑人民币 | 腾讯 `qt.gtimg.cn` | HTTP GET | `fxUSDCNY` |
| 上海黄金 AU99.99 | 上海黄金交易所 `sge.com.cn` | HTTP POST | `Au99.99` |
| 上海白银 Ag99.99 | 上海黄金交易所 `sge.com.cn` | HTTP POST | `Ag99.99` |

> ⚠️ SGE 白银原始单位是**元/千克**，需用 `scale: 0.001` 换算成**元/克**。

### 取数实现（`market_data.py`，纯标准库）
- `get_snapshot(prev)` 统一返回所有品种快照；伦敦现货 / SGE 无日内涨跌，用上一轮快照推算 `change_pct`。
- `_http_get` 带 3 次重试 + backoff，规避公开行情接口偶发超时。

### 单位换算规则
- config 中 `scale` 只作用于**价格字段**（`latest`/`prev_close`/`open`/`high`/`low`），**不**作用于涨跌幅 / 成交量。
- `main()` 读取旧快照时**先按 scale 还原为来源原始单位**，再传给 `market_data`——否则跨单位比较会算出 +99900% 的假警报。

### 衍生品计算
- **上海黄金夜盘估算（computed 类型）**：`COMEX黄金 × USDCNY ÷ 31.1035`（USD/oz → CNY/g）。
  - 中国市场休市 → 实时跟踪外盘；开市 → 用 COMEX 昨结冻结为隔夜参考（`change_pct=None`，标注"开市(隔夜参考)"）。
- **active_hours 守卫**：北京时间窗口外跳过整轮刷新，保留旧数据、避免误报（`is_active_now` 支持跨午夜窗口）。

## 2. 云端自动化（GitHub Actions）

### 调度控制点
- 唯一执行计划来源 = 仓库 `.github/workflows/gold-monitor.yml` 的 `cron` 行。
- WorkBuddy 本地自动化（`automation-1785250729087`）已废弃并置 PAUSED。
- 当前 cron（UTC，北京时间 = UTC+8）：`0 21-23,0-16 * * *` = 北京时间 **05:00–24:00 每小时一次**。

### 修改计划的方法
1. 网页直接编辑 `https://github.com/AkashHuang/gold-dashboard/edit/main/.github/workflows/gold-monitor.yml`；
2. 或告诉我要改什么（如"每 30 分钟"、"只工作日"），我经 Contents API 推送。

### CI 代码安全
- `GITHUB_ACTIONS=1` 时跳过本地 publish，从环境变量注入 `SERVERCHAN_SENDKEY` / `ALERT_EMAILS`（避免把密钥提交到公开仓库）。
- `send_serverchan` 用 stdlib `urllib`，CI 无需 `pip install`。

### 本地 → 云端推送
- 改完经 **Contents API**（PAT，存 `~/.workbuddy/github_pat.txt`，权限 600）推送。
- 沙箱代理屏蔽 git，不能用 `git clone` / `git push`。
- PAT 仅需 `contents` 权限；`Actions: Read and write` 仅给远程 `workflow_dispatch` 手动触发用，**cron 自动触发不需要**。

### 时间显示坑（当天已修复）
- CI runner 默认 **UTC**，`render_dashboard` 必须用 `beijing_now`（`get_beijing_time()`）而非 `datetime.now()`，否则刷新时间偏 8 小时。

  - **云端 CI 内邮件目前仅写入 `alerts_pending.json`、不实际发送**（待接入 agent-mail 或 GitHub 原生邮件 secret）。

### 触发规则
| 类型 | 规则 | 备注 |
|------|------|------|
| 常规品种 | `abs(较昨收涨跌幅) ≥ threshold`（默认 1.0%） | 带 cooldown（默认 4h）防刷 |
| 金银涨幅比（momentum） | `白银涨% / 黄金涨% ≥ 2` | **需银、金均上涨**（both_positive 守卫），避免同跌误触发 |
| 美金银比 | 比值落入 `[50,55]`（band_alert） | 落入区间即触发 |
| 伦敦/上海金银比 | `no_alert` | 仅展示，不提醒 |
| 波动记录 | 保留 `record_retention_hours`（默认 24h） | 按窗口清理 + 截断 100 条 |
