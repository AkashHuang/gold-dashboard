## 1. 贵金属价格获取方法

### 数据源（2026-07-29 起弃用 NeoData）
NeoData 不覆盖白银现货、且需付费接口。改为以下**免费公开、无需 token** 的源：

| 品种 | 来源 | 方式 | 代码 / 标识 |
|------|------|------|------|
| COMEX 黄金期货 | 腾讯 `qt.gtimg.cn` | HTTP GET（GBK 解码） | `fuGC` |
| COMEX 白银期货 | 腾讯 `qt.gtimg.cn` | HTTP GET | `fuSI` |
| 伦敦金现货 | 腾讯 `qt.gtimg.cn` | HTTP GET | `hf_XAU` |
| 伦敦银现货 | 腾讯 `qt.gtimg.cn` | HTTP GET | `hf_XAG` |
| 美元兑人民币 | 腾讯 `qt.gtimg.cn` | HTTP GET | `fxUSDCNY` |
| 上海黄金 AU99.99 | 上海黄金交易所 `sge.com.cn` | HTTP POST | `Au99.99` |
| 上海白银 Ag99.99 | 上海黄金交易所 `sge.com.cn` | HTTP POST | `Ag99.99` |

> ⚠️ SGE 白银原始单位是**元/千克**，需用 `scale: 0.001` 换算成**元/克**。

### 取数实现（`market_data.py`，纯标准库）
- `get_snapshot(prev)` 统一返回所有品种快照；伦敦现货 / SGE 无日内涨跌，用上一轮快照推算 `change_pct`。
- `_http_get` 带 3 次重试 + backoff，规避公开行情接口偶发超时。

### 单位换算规则
- config 中 `scale` 只作用于**价格字段**（`latest`/`prev_close`/`open`/`high`/`low`），**不**作用于涨跌幅 / 成交量。
- `main()` 读取旧快照时**先按 scale 还原为来源原始单位**，再传给 `market_data`——否则跨单位比较会算出 +99900% 的假警报。

### 衍生品计算
- **上海黄金夜盘估算（computed 类型）**：`COMEX黄金 × USDCNY ÷ 31.1035`（USD/oz → CNY/g）。冻结规则见 §4.2「夜盘估算逻辑（选项 A）」——仅 02:30–09:00 休市间隙冻结为隔夜参考，其余时段实时跟踪外盘。
- **active_hours 守卫**：北京时间窗口外跳过整轮刷新，保留旧数据、避免误报（`is_active_now` 支持跨午夜窗口）。

## 2. 云端自动化（GitHub Actions）

### 调度控制点
- 唯一执行计划来源 = 仓库 `.github/workflows/gold-monitor.yml` 的 `cron` 行。
- WorkBuddy 本地自动化（`automation-1785250729087`）已废弃并置 PAUSED。
- 当前 cron（UTC，北京时间 = UTC+8）：`0 21-23,0-16 * * *` = 北京时间 **05:00–24:00 每小时一次**。

### 修改计划的方法
1. 网页直接编辑 `https://github.com/AkashHuang/gold-dashboard/edit/main/.github/workflows/gold-monitor.yml`；
2. 或告诉我要改什么（如"每 30 分钟"、"只工作日"），我经 Contents API 推送。

### CI 代码安全
- `GITHUB_ACTIONS=1` 时跳过本地 publish，从环境变量注入 `SERVERCHAN_SENDKEY` / `ALERT_EMAILS`（避免把密钥提交到公开仓库）。
- `send_serverchan` 用 stdlib `urllib`，CI 无需 `pip install`。

### 本地 → 云端推送
- 改完经 **Contents API**（PAT，存 `~/.workbuddy/github_pat.txt`，权限 600）推送。
- 沙箱代理屏蔽 git，不能用 `git clone` / `git push`。
- PAT 仅需 `contents` 权限；`Actions: Read and write` 仅给远程 `workflow_dispatch` 手动触发用，**cron 自动触发不需要**。

### 时间显示坑（当天已修复）
- CI runner 默认 **UTC**，`render_dashboard` 必须用 `beijing_now`（`get_beijing_time()`）而非 `datetime.now()`，否则刷新时间偏 8 小时。

### 触发规则
| 类型 | 规则 | 备注 |
|------|------|------|
| 常规品种 | `abs(较昨收涨跌幅) ≥ threshold`（默认 1.0%） | 带 cooldown（默认 4h）防刷 |
| 金银涨幅比（momentum） | `白银涨% / 黄金涨% ≥ 2` | **需银、金均上涨**（both_positive 守卫），避免同跌误触发 |
| 美金银比 | 比值落入 `[50,55]`（band_alert） | 落入区间即触发 |
| 伦敦/上海金银比 | `no_alert` | 仅展示，不提醒 |
| 波动记录 | 保留 `record_retention_hours`（默认 24h） | 按窗口清理 + 截断 100 条 |

> **2026-07-30 更新 — 合并提醒**：每次刷新仅发 **1 条** ServerChan 消息（标题 `黄金看板提醒 · N 条预警`），将本轮所有触发项合并，各触发项以 `---` 分隔；不再按品种逐条发送。`build_alert_messages` 的 `now_str` 改用 `get_beijing_time()`（修复此前 UTC 显示偏差）。

## 4. 各品种逻辑说明（含市场时段与状态点）

### 4.1 市场时段与状态点（open/closed 逻辑）
仪表板每张卡片左上角的圆点：`● 绿 = 交易中`，`○ 空心 = 休市`；顶部有图例。判定函数 `is_market_open(market, beijing_dt)`，按市场分派：

| 市场 | 交易时段（北京时间） | 周末 | 夏/冬令处理 |
|------|------|------|------|
| COMEX（纽约金/银期货） | ≈23×5；每日约 1 小时**结算间隙**（夏令 05:00–06:00 / 冬令 06:00–07:00） | 休市 | `_us_dst_active` 区分；间隙起始 `brk=5`(夏)/`6`(冬) |
| 伦敦现货 | 当地 08:00–17:00 → 夏令 15:00–24:00；冬令 16:00–次日 01:00 | 休市 | `_uk_dst_active` 区分 |
| SGE（上海黄金） | 日盘 09:00–11:30 / 13:30–15:30；夜盘 20:00–次日 02:30 | 周日休市 | — |
| FX（美元兑人民币） | 约 09:30–23:30 | 休市 | — |

> ⚠️ COMEX 并非"24×5"：每日有约 1 小时结算/维护间隙，故准确说是 **≈23×5**。若仪表板显示 COMEX 休市，多为落在结算间隙，或快照停留在间隙内的那次刷新（状态点按刷新时刻计算，非实时）。

### 4.2 12 个品种逐一说明

| # | ID | 类型 | 名称 | 数据源 | 计算 / 口径 | 提醒逻辑 | 备注 |
|---|----|------|------|--------|------------|----------|------|
| 1 | comex_gold | data | COMEX 黄金 | 腾讯 gtimg `fuGC` | 实时价 + 较昨收涨跌幅 | 常规 `abs(涨跌幅)≥1%` + 4h cooldown | 美元/盎司，成交量"手" |
| 2 | comex_silver | data | COMEX 白银 | 腾讯 gtimg `fuSI` | 同上 | 同上 | 美元/盎司 |
| 3 | comex_ratio | ratio | 美金银比 | 由 comex_gold / comex_silver 计算 | 比值 = 金价 ÷ 银价 | band `[50,55]` + `band_alert` → 落入即触发 | **唯一**触发区间提醒的金银比 |
| 4 | silver_gold_momentum | momentum | 金银涨幅比 | 白银涨% ÷ 黄金涨% | 比值 ≥ 2 触发 | 需银、金**均上涨**（both_positive），否则不触发 | 卡片排在 comex_ratio 之后 |
| 5 | london_gold | data | 伦敦金 | 腾讯 gtimg `hf_XAU` | 实时价 + 涨跌幅 | 常规 | 美元/盎司 |
| 6 | london_silver | data | 伦敦银 | 腾讯 gtimg `hf_XAG` | 同上 | 常规 | 美元/盎司 |
| 7 | london_ratio | ratio | 伦敦金银比 | london_gold / london_silver | 比值 | band `[50,55]` + `no_alert` → 仅展示不提醒 | — |
| 8 | shanghai_gold | data | 上海黄金 AU99.99 | SGE `sge.com.cn` POST | 实时价 + 涨跌幅 | 常规 | 元/克 |
| 9 | shanghai_gold_night | computed | 上海黄金（夜盘估算） | 由 `comex_gold × fx.usdcny / 31.1035` 计算 | 见下「夜盘估算逻辑」 | 常规（threshold 1.0） | **非真实 SGE 数据**，是外盘换算估算 |
| 10 | shanghai_silver | data | 上海白银 | SGE POST | 实时价 + 涨跌幅 | 常规 | 原始 元/千克，`scale:0.001` → 元/克 |
| 11 | shanghai_ratio | ratio | 上海金银比 | shanghai_gold / shanghai_silver | 比值 | band `[50,55]` + `no_alert` → 仅展示 | — |
| 12 | fx | data | 美元兑人民币 | 腾讯 gtimg `fxUSDCNY` | 实时汇率 | 常规 | 无单位；供夜盘估算与 USDCNY 换算 |

**夜盘估算逻辑（2026-07-30 选项 A）**：`值 = COMEX黄金 × USDCNY ÷ 31.1035`（USD/oz → CNY/g）。
- 仅当北京时间落在 **02:30–09:00 休市间隙**时，用 COMEX **昨结价**冻结为隔夜参考（`change_pct=None`，标注"隔夜参考"）；
- 其余时段（夜盘 20:00–02:30、日盘 09:00–15:30）均**实时跟踪 COMEX 最新价**（标注"实时估算"）。
- 即北京 1:00 等夜盘进行中时，估算来自最新外盘价、不冻结。
